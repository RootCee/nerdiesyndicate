## Preview sequence (non-production)

The Vercel preview hostname is not known until Vercel creates the preview
deployment. It must be recorded exactly before configuring preview CORS; do not
guess a branch alias or reuse the production Worker.

1. Push the website candidate branch to the connected Git remote to let Vercel
   create a preview:

   ```sh
   cd /Volumes/T7/NerdieBlaq/NerdieCity-MafiaWars/website-m6-3-rc
   git push origin codex/mafia-wars-m6-3-production-rc
   ```

2. Record the exact preview deployment URL and deployment ID from Vercel. Prepare
   a separate preview Worker configuration with name
   `nerdie-city-m6-3-preview`, `ROOMS` bound to `MultiplayerRoom`, migration `v1`,
   and `ALLOWED_ORIGINS` set to only that exact HTTPS preview origin. Review the
   full configuration and preview target before deploying it.

3. From the source candidate's `multiplayer` directory, deploy only the preview
   configuration after approval:

   ```sh
   cd /Volumes/T7/NerdieBlaq/NerdieCity-MafiaWars/source/multiplayer
   npx wrangler deploy --config wrangler.m6-3-preview.toml
   ```

4. Verify preview `/health` reports protocol 4, capacity 20, and Underground
   capacity 12. The Worker requires an allowed `Origin` header:

   ```sh
   curl -H 'Origin: https://<exact-preview-host>' \
     https://nerdie-city-m6-3-preview.buddieroots.workers.dev/health
   ```

   Use two real clients (Mac and iPhone on Wi-Fi) to verify join, movement,
   public-city damage, safe-zone protection, death/respawn, and Underground
   access. Do not use production credentials or the production Worker for
   preview tests.

The preview configuration file and exact preview origin are deliberately not
fabricated here; the preview origin has not been issued by Vercel. Do not point
the preview client at the production Worker.

## Production sequence (requires separate final approval)

1. Complete the preview and two-device smoke test above. Present the exact
   website candidate commit, preview URL/deployment ID, Worker target/config,
   expected Worker source commit, and rollback commands for final approval.
2. Deploy the Worker from the source candidate, after approval:

   ```sh
   cd /Volumes/T7/NerdieBlaq/NerdieCity-MafiaWars/source/multiplayer
   npx wrangler deploy --config wrangler.protocol-4-1-production.toml
   ```

   Confirm the target name is exactly `nerdie-city-multiplayer-v4`, inspect the
   Durable Object binding and migration plan, and verify the Worker version ID.
   The candidate retains migration `v1`; it must not create a new namespace or
   apply a destructive migration.
3. Check `https://nerdie-city-multiplayer-v4.buddieroots.workers.dev/health` for
   protocol `4`, capacity `20`, and Underground capacity `12`:

   ```sh
   curl -H 'Origin: https://nerdieblaq.xyz' \
     https://nerdie-city-multiplayer-v4.buddieroots.workers.dev/health
   ```
4. Promote the exact preview deployment that passed device testing:

   ```sh
   cd /Volumes/T7/NerdieBlaq/NerdieCity-MafiaWars/website-m6-3-rc
   vercel promote https://<verified-preview-deployment>.vercel.app
   ```

   Record the resulting production deployment ID and verify the domain serves
   the approved candidate commit. This promotes the tested preview build; it
   does not rebuild from `main`. The website project deploys the whole site, so
   confirm the candidate diff contains no unrelated route changes. Vercel
   documents this workflow at
   <https://vercel.com/docs/deployments/promote-preview-to-production>.
5. Run two-device checks at `https://nerdieblaq.xyz/mafia-wars`, including
   movement, combat, apartment safe-zone protection, respawn, and Underground
   access. Check unrelated website routes as a smoke test.

## Rollback and partial-deployment recovery

- Frontend rollback: use Vercel Instant Rollback to deployment
  `dpl_2EKvNMToo4pzxPmwAmFoG86Tx6hj`, or, from the authenticated linked project,
  run:

  ```sh
  vercel rollback dpl_2EKvNMToo4pzxPmwAmFoG86Tx6hj
  ```

- Worker rollback: from the authenticated Cloudflare account, run:

  ```sh
  cd /Volumes/T7/NerdieBlaq/NerdieCity-MafiaWars/source/multiplayer
  npx wrangler rollback 55ed4286-c4dd-4180-9552-3f7ce2cfeae6 \
    --name nerdie-city-multiplayer-v4
  ```

- If the Worker deploy succeeds but the frontend release does not, immediately
  roll the Worker back to the known previous version and verify `/health`.
- If the frontend deploy succeeds but the Worker deploy fails, roll the frontend
  back first; do not leave the new client live against an unverified backend.
- If both deploy but the smoke test fails, roll back the frontend, then the
  Worker, and verify both restored versions. Existing Durable Object records are
  retained; rollback does not delete room data. During Worker rollback, rooms
  created under the 20-player release may remain present but the prior six-player
  admission limit applies.
- Do not run `wrangler delete`, remove Durable Object namespaces, or change
  migration history as a rollback method.
